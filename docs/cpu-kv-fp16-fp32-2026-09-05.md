# FP16 versus FP32 KV cache on the optimized CPU attention path

FP32 cache storage works with the existing optimized AVX2 attention kernels,
including paired-query GQA decode. The kernels already select FP32 loads when
the optional FP16 pointers are null. The runtime now exposes that path through
`--cpu-kv-cache fp16|fp32` without changing weight quantization, activation
quantization, DeltaNet state precision, SIMD dispatch, or thread count.

The default remains FP16. For quantized CPU inference, FP32 suppresses the
FP16 sidecar allocation and its per-token conversion. Attention arithmetic
remains FP32 in both modes. Scalar and unquantized reference inference use
FP32 regardless of the preference. The actual selection is printed and saved
as `cpu_kv_cache` in profile JSON and benchmark CSV.

## Results

Host: AMD Ryzen 9 9955HX3D, Windows, MSVC 19.44.35219, Ninja Release CPU-only
build. Both modes use the same `build-cpu-kv/qwen35x.exe`, 12 threads,
`avx512-vnni`, and `model-q4-h128-cpu-x8.q35h`. The attention implementation is
AVX2 under this ISA setting; it is not the scalar fallback.

All measurements used `scripts/benchmark-inference-seq.ps1` sequentially,
three measured runs after one warmup per block, two blocks per precision.
Context capacity 256; 128 output tokens for decode. Prefix and session caches
were disabled. Throughput excludes model loading. The one-token prompt is
token `1`; longer prompts use the first 128/256 tokens from
`configs/qwen3_5_0_8b_text_1024x512_tokens.csv`.

The primary decode comparison forces the same 128-token continuation in both
precisions, taken from an initial FP16 greedy run. This isolates the comparison
from different generated continuations. No logit dumps were enabled during
timing. Teacher forcing uses the materialized-logit path in both modes, so
absolute numbers should not be equated with the fused-greedy measurements.

Medians of six measured runs per mode and workload:

| Workload | FP16 | FP32 | FP32 throughput change |
| --- | ---: | ---: | ---: |
| 1 input + 128 identical forced output tokens | 127.72 tok/s | 127.98 tok/s | +0.2% |
| 128 input + 128 identical forced output tokens | 125.39 tok/s | 124.24 tok/s | -0.9% |
| 256-token prefill only | 1,174.53 tok/s | 1,113.77 tok/s | -5.2% |

Forced-decode arithmetic means are 127.88/127.93 tok/s (one-token prompt) and
124.58/124.13 tok/s (128-token prompt). The ranges overlap substantially, so
the decode result is effectively neutral at these context sizes. FP32 prefill
is consistently slower in this sample: FP16 range 1,152.26–1,181.88 tok/s,
FP32 range 1,102.13–1,149.22 tok/s. No long-context conclusion is implied.

An initial ordinary greedy A/B/B/A sweep measured median decode
128.30/124.98 tok/s at prompt length 1 and 126.13/123.24 at prompt length 128.
The output sequences diverged at zero-based output indices 43 and 89,
respectively. A second B/A/A/B sweep therefore used identical forced
trajectories; its more controlled results are the primary decode figures
above. All runs, including the initial sweep, are retained in the
[individual measurements](cpu-kv-fp16-fp32-2026-09-05.csv). These are separate
measurement cohorts; the difference between them should not be attributed
solely to the token trajectories.

For this workload, FP32 is an available precision tradeoff with no established
decode penalty, but about a 5% prefill-throughput penalty. FP32 avoids cache
rounding; these measurements do not establish improved answer quality.

## Numerical and cache checks

- All seven CTest targets pass. Paired GQA tests now cover both FP16 and FP32
  cache loads over head dimensions 17/256 and eleven contexts from 1 to 2048,
  on all available backends.
- The optional full-model `qwen35x_cpu_kv_cache_model_test` compares complete
  logits byte-for-byte for uncached and cached inference with a 65-token
  prompt, 64-token prefix and three forced output tokens. It switches
  FP16 -> FP32 -> FP16 on one persistent model session and verifies snapshot
  invalidation on precision changes and successful reuse within each mode.
- The prefix snapshot now records its effective precision. Snapshot capture
  previously selected FP16 only for an exact `avx2` backend, omitting VNNI and
  AVX-512 backend values even though they read FP16 too. Capture now uses the
  actual cache allocation; the in-memory state ABI is incremented.
- In a separate eight-position teacher-forced check, FP32 versus FP16 full
  logits have mean KL 0.0009554, maximum KL 0.0017052, and 100% raw top-1
  agreement. FP32 is just the comparison reference here, not a BF16 quality
  teacher. The forced continuation repeats tokens `19,13,198`; this is a
  numerical smoke test, not a held-out quality evaluation.
- Every mode is deterministic across its six measured greedy runs. The
  twelve forced outputs per prompt length are identical across modes.

The six full-attention layers use 3 MiB of FP16 KV storage at capacity 256,
plus the existing 6 MiB FP32 mirror. FP32 mode uses only the 6 MiB FP32 copy.
Thus this implementation actually allocates **6 MiB instead of 9 MiB** for
full-attention KV data in FP32 mode. DeltaNet state is separate and unchanged.

## Usage and reproduction

No new checkpoint is needed. Add `--cpu-kv-cache fp32` to the CPU invocation:

```powershell
.\scripts\build.ps1 -UseNinja -Configuration Release -BuildDir build-cpu-kv -BuildAll
.\build-cpu-kv\qwen35x.exe --infer-reference `
  --hf-model-dir models/qwen3.5-0.8b `
  --cpu-q4-h128 models/qwen3.5-0.8b/model-q4-h128-cpu-x8.q35h `
  --cpu-threads 12 --cpu-isa avx512-vnni --cpu-kv-cache fp32 `
  --chat-user "Was ist 2 + 2?" --temperature 0 --max-new-tokens 128 --max-context 256

ctest --test-dir build-cpu-kv --output-on-failure
.\build-cpu-kv\qwen35x_cpu_kv_cache_model_test.exe `
  models/qwen3.5-0.8b models/qwen3.5-0.8b/model-q4-h128-cpu-x8.q35h
```

The benchmark runner accepts `-CpuKvCache fp16|fp32` and optional
`-ForcedOutputTokensCsv` (the count must match `-MaxNewTokens`). Example:

```powershell
$trajectory = Get-ChildItem benchmarks/cpu-kv-profiles/run*.json |
  ForEach-Object { Get-Content $_.FullName -Raw | ConvertFrom-Json } |
  Where-Object { $_.cpu_kv_cache -eq 'fp16' -and $_.prompt_tokens -eq 1 -and $_.generated_tokens -eq 128 } |
  Select-Object -First 1
.\scripts\benchmark-inference-seq.ps1 `
  -Executable build-cpu-kv/qwen35x.exe -Modes cpu-h128 `
  -CpuQ4H128 models/qwen3.5-0.8b/model-q4-h128-cpu-x8.q35h `
  -CpuThreads 12 -CpuIsa avx512-vnni -CpuKvCache fp32 `
  -PromptMode prompt-tokens -PromptTokensCsv 1 `
  -ForcedOutputTokensCsv ($trajectory.output_token_ids -join ',') `
  -Runs 3 -WarmupRuns 1 -MaxNewTokens 128 -MaxContext 256 `
  -CsvOut benchmarks/cpu-kv-reproduction.csv -KeepProfiles
```

Full local measurements: `benchmarks/cpu-kv-fp16-fp32-2026-09-05.csv` and
`benchmarks/cpu-kv-forced-2026-09-05.csv`. Profiles are retained in
`benchmarks/cpu-kv-profiles/` and `benchmarks/cpu-kv-forced-profiles/`.
