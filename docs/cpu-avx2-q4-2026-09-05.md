# AVX2 Q4 kernel experiments on i7-8750H, 2026-09-05

The retained change computes packed Q4/Q8 integer dot products in the existing eight-byte row chunks, then reduces across rows. It improves AVX2 throughput without changing the checkpoint, quantization, FP32 scale multiplication, or cross-block FMA order. The separate H128 transform experiment was reverted after its apparent additional prefill gain failed a repeat comparison.

## Format compatibility

The CPU-X8 artifact is shared by scalar, AVX2 and VNNI backends. Commit `6fc92f4` moved the existing runtime packing into the converter and removed four sign-XOR instructions from the AVX2 kernel. Its shuffle/blend structure predates that artifact change; it was not introduced to accommodate AVX-512. The retained optimization reads exactly the same bytes. No regeneration or ISA-specific artifact is needed.

## Retained AVX2 change

- Broadcast eight Q8 activation bytes per packed row chunk instead of broadcasting four-byte groups and blending the weights into dot-product lane order.
- Accumulate four pair-product vectors in signed 16-bit lanes, then widen and horizontally reduce. Each partial lane contains at most eight unsigned-Q4/signed-Q8 products: `8 * 15 * 128 = 15360`, safely inside int16. The pairwise saturating multiply-add is safe too. This includes externally supplied Q8 bytes of -128.
- Preserve the established row permutation, subtraction of `8 * activation_sum`, scale product, and FMA sequence. The same helper handles one-token decode and four/eight-token prefill.
- Remove the two helper functions made obsolete by the new calculation. AVX-VNNI and AVX-512-VNNI translation units are unchanged.

GCC 15.2 generated the following instruction counts in the prepared AVX2 decode inner loop (not whole-model instruction counts):

| Instruction | Original | Retained |
|---|---:|---:|
| `vpblendd` | 8 | 0 |
| `vpshufd` | 16 | 1 |
| `vpmaddubsw` | 8 | 8 |
| `vpmaddwd` | 8 | 2 |
| `vpaddd` | 7 | 0 |
| `vpaddw` | 0 | 6 |
| `vphaddd` | 0 | 1 |

## Method

- Base: `e9cdd44`, retained unmodified executable at `build-cpu-avx2-baseline/qwen35x`. Final executable: `build-cpu-packed/qwen35x`.
- Intel Core i7-8750H, 6 physical cores / 12 logical CPUs; Linux x86_64, GCC 15.2.0, Ninja Release CPU-only build.
- Six inference threads throughout, explicit AVX2, FP16 KV cache, no prefix reuse or imposed affinity. No thread sweep; six threads were already established by the user.
- Every timing run used `scripts/benchmark-inference-seq.ps1`: three measured runs after one warmup, max new tokens 128, max context 256. No concurrent build, conversion, test, or benchmark processes.
- Fresh process per run, warm OS file caches. Greedy decode from token `1` (`decode1`) or the first 128 tokens of `configs/qwen3_5_0_8b_text_1024x512_tokens.csv` (`decode128`). `prefill256` uses the first 256 tokens and `-PrefillOnly`.
- Main block order: baseline-A1, q4-B1, h128-C1, combined-D1, q4-B2, combined-D2, baseline-A2. Each block contains decode1, decode128 and prefill256. No runs discarded.
- Final H128 isolation: prefill-only q4-E1, combined-F1, combined-F2, q4-E2. These targeted runs are kept separately from the main-round aggregates.

## Main-round results

Medians across six measurements per baseline/retained workload (two three-run blocks). These are new comparison runs, not percentages calculated against the earlier one-off host benchmark.

| Workload | Original tok/s | Retained Q4 tok/s | Change |
|---|---:|---:|---:|
| decode1 | 63.32 | 65.34 | +3.19% |
| decode128 | 62.53 | 64.86 | +3.72% |
| prefill256 | 315.92 | 376.30 | +19.11% |

The observed decode improvement is modest and individual ranges overlap; the prefill gain is larger and appears in both main rounds. Clock/thermal conditions and scheduling were not controlled beyond sequential execution, so these are local observations, not guarantees for other CPUs or workloads. No hardware-counter diagnosis of the remaining bottleneck is claimed.

## Rejected H128 transform

The trial replaced the first three butterfly stages with sign-XOR/partner-add operations, completed each 64-value half in eight AVX2 vectors, then combined the halves. The emitted signed transform had no stack references, and correctness checks passed, including signed zeros, cancellation, impulses, mixed exponents, in-place operation, multiple seeds, and full-model logits.

With the original Q4 kernel, its first-round decode1/decode128/prefill256 medians were 63.53/63.06/320.84 tok/s, essentially matching the adjacent first baseline round (63.54/63.05/320.70). Combined with the new Q4 kernel, the initial rounds suggested a small extra prefill gain. The targeted repeat did not confirm that gain:

| Targeted prefill block | Median tok/s |
|---|---:|
| q4-prefill-E1 | 370.29 |
| combined-prefill-F1 | 370.42 |
| combined-prefill-F2 | 370.19 |
| q4-prefill-E2 | 378.73 |

The final source retains the original H128 implementation. Experimental binaries, source copies, tests and disassembly remain under the ignored `benchmarks/qwen-cpu/avx2-experiments/` directory for inspection.

## Validation

- All seven CTest suites pass. The retained Q4 regression adds exact scalar comparisons for extreme Q4/Q8 values, negative scales, distinct rows/blocks, twelve-token prefill (8+4), and prepared single-token matvec.
- Original versus Q4-only, H128-only, combined and final builds: three teacher-forced full-vocabulary logit vectors are byte-identical for each of 1-, 65- and 128-token prompts. The 65-token case exercises a 64-token prefill tile plus a one-token remainder.
- All 75 measured output token arrays match by workload; each of the 42 measured decode runs generates the same 128 token IDs as its baseline workload.
- Packed artifact remains `models/qwen3.5-0.8b/model-q4-h128-cpu-x8.q35h`, SHA-256 `ba3fa90884e6fd4690a40c45af982c3ca9a38badb05ae865d4597fe71efe1cde`.
- AVX-512/VNNI execution was not available on this host. Their kernels were not modified.

## Reproduction and artifacts

```bash
bash scripts/build.sh --ninja --no-cuda --config Release --build-dir build-cpu-packed --all
ctest --test-dir build-cpu-packed --output-on-failure
pwsh -NoProfile -File benchmarks/qwen-cpu/avx2-experiments/run.ps1 -Executable build-cpu-packed/qwen35x -Label retained
python3 benchmarks/qwen-cpu/avx2-experiments/check-parity.py final
```

The local wrapper uses the repository PowerShell benchmark and saves all per-run JSON profiles. PowerShell for these runs is `/tmp/qwen-pwsh/pwsh`. The tracked [CSV](cpu-avx2-q4-2026-09-05.csv) contains all 75 measured rows; the full local CSV, build/run logs and profiles are in `benchmarks/qwen-cpu/avx2-experiments/`. The comparison requires keeping the unmodified baseline executable.
