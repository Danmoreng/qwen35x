# CPU-ready Q4 H128 packing

The converter now writes the CPU projection layout directly. Loading the new
artifact reads quantized tensors into their final `Q4_0BlockX8` buffers and
validates their checksums, without canonical staging, projection concatenation,
scale sidecars, or runtime repacking. The packed kernels also no longer undo a
sign-bit XOR on every weight block. Quantization and activation preparation are
unchanged.

## Artifact contract

The version-1 container gains two explicit tensor encodings: `q4_0_cpu_x8 = 3`
and `q4_h128_cpu_x8 = 4`. Old readers reject these unknown encodings. The new
reader continues to support canonical encodings 1 and 2, and GGUF loading still
packs canonical Q4 into the new internal representation.

Each packed matrix has a row count divisible by eight and a column count
divisible by 32 (128 for transformed weights). In row-tile-major,
input-block-minor order, each 144-byte block contains:

- Eight consecutive little-endian FP16 scales, in output-row order.
- 128 Q4 bytes in two chunks of 64 bytes; each chunk contains eight bytes per
  output row. Low/high nibbles retain the canonical `q + 8` encoding, with no
  sign-bit flip. Low nibbles represent input columns 0–15; high nibbles 16–31.

The converter merges these projections in the stated row order:

- `mlp.gate_up_proj.weight`: gate, up.
- `linear_attn.in_proj_all.weight`: QKV, Z, B, A.
- `self_attn.qkv_proj.weight`: Q, K, V.

Embedding/tied LM-head weights use encoding 3; transformed projections use
encoding 4. F32 tensors keep their existing representation. Small convolution
and DeltaNet parameter preparation still occurs at load time; this change
precomputes the quantized projection layout. Activation H128/Q8 preparation and
Q4 nibble unpacking inside the integer kernels remain necessary.

The artifact remains approximately the same size: **424,964,864 bytes**, versus
424,976,960 bytes before. The smaller directory accounts for the difference;
there is no enlarged or duplicate permanent weight representation. There are
230 final tensors versus 320 canonical source tensors.

## Local artifact and build

Source: `models/qwen3.5-0.8b/model.safetensors-00001-of-00001.safetensors`;
the text projection dtype is BF16. Conversion reads the source safetensors,
never the old quantized artifact.

```powershell
.\scripts\build.ps1 -UseNinja -Configuration Release -BuildDir build-cpu-packed -BuildAll
.\build-cpu-packed\qwen35x_q4_h128_convert.exe `
  --hf-model-dir models/qwen3.5-0.8b `
  --output models/qwen3.5-0.8b/model-q4-h128-cpu-x8.q35h
```

`--layout cpu-packed` is now the converter default. `--layout canonical`
retains the previous artifact representation. Existing output files are never
overwritten.

New artifact SHA-256:
`ba3fa90884e6fd4690a40c45af982c3ca9a38badb05ae865d4597fe71efe1cde`.

Old canonical artifact SHA-256:

## Correctness

- All seven CTest targets pass. Artifact tests cover both new encodings,
  incomplete row/column tiles, wrong transform metadata, direct reads, buffer
  size/null errors, and corrupted payload checksums.
- `scripts/verify-q4-h128-packing.py` independently reconstructs the packed
  layout with NumPy and verifies every source tensor is represented exactly
  once. All FP16 scales, Q4 nibbles and F32 bytes match the old artifact exactly.
- Eight teacher-forced arithmetic positions produce byte-identical full-logit
  files between the original binary/artifact and new binary/artifact.
- A 65-token prompt exercises the 64-token prefill chunk plus its one-token
  remainder. Across three forced output positions, full-logit files are
  byte-identical between original build, new build/new artifact, and new
  build/old artifact, separately for scalar, AVX2 and AVX-512-VNNI dispatch.
- All twelve measured 128-token decode outputs (six old, six new) are identical.
- A final session/prefix replay smoke run loads the packed artifact and reports
  a session hit and four cached prefix tokens successfully.

```powershell
ctest --test-dir build-cpu-packed --output-on-failure
python scripts/verify-q4-h128-packing.py `
  models/qwen3.5-0.8b/model-q4-h128.q35h `
  models/qwen3.5-0.8b/model-q4-h128-cpu-x8.q35h
```

## Sequential performance comparison

Host: Ryzen 9 9955HX3D, Windows, 16 physical/32 logical cores; 12 inference
threads, explicit `avx512-vnni`, MSVC 19.44.35219, Ninja Release CPU-only builds
with identical configuration. No affinity was imposed. Baseline is unmodified
commit `0cfb1b002025953f29790490416ad84040fba651`, retained in
`build-cpu-packed-baseline`. It was built and measured before inference edits.

Every measurement used `scripts/benchmark-inference-seq.ps1`: three measured
runs after one warmup, context 256, maximum new tokens 128. Decode uses prompt
token `1`; prefill-only uses the first 256 tokens of
`configs/qwen3_5_0_8b_text_1024x512_tokens.csv`. Each run starts a fresh process,
with warm OS file caches and no session or prefix-cache reuse. Load time is
reported separately from inference throughput.

Two blocks per variant were collected in A/B/B/A order (each block includes
decode and prefill). Medians across six runs per variant/workload:

| Metric | Original | CPU-packed | Change |
| --- | ---: | ---: | ---: |
| Model load, decode workload | 914.24 ms | 573.57 ms | **37.3% less time** |
| Prefill, 256 tokens | 1,109.98 tok/s | 1,176.71 tok/s | **+6.0%** |
| Decode, 128 tokens | 127.12 tok/s | 129.21 tok/s | **+1.6%** |

Arithmetic means are 918.98/577.01 ms load, 1,109.37/1,178.28 tok/s prefill
(+6.2%), and 125.53/128.96 tok/s decode (+2.7%). One baseline decode run dropped
to 117.49 tok/s; it is retained in all results, and makes the mean gain look
larger. The median is the more conservative summary. Decode ranges overlap;
this is a small observed gain, not a guarantee on other hosts. The original
first three decode runs average 126.69 tok/s versus 128.97 for the first new
three (+1.8%). No discarded runs or concurrent benchmark processes.

[Individual measurements](q4-h128-cpu-packing-2026-09-05.csv) are stored beside
this report. Full local CSV: `benchmarks/q4-packed-2026-09-05.csv`; profiles:
`benchmarks/q4-packed-profiles/`. The new `cpu-h128` benchmark mode records the
artifact path separately from GGUF.

Example decode benchmark (use the old executable/artifact for baseline):

```powershell
.\scripts\benchmark-inference-seq.ps1 `
  -Executable build-cpu-packed/qwen35x.exe -Modes cpu-h128 `
  -CpuQ4H128 models/qwen3.5-0.8b/model-q4-h128-cpu-x8.q35h `
  -CpuThreads 12 -CpuIsa avx512-vnni -Runs 3 -WarmupRuns 1 `
  -MaxNewTokens 128 -MaxContext 256 -PromptMode prompt-tokens `
  -PromptTokensCsv 1 -PromptName decode1 -RunLabel packed `
  -CsvOut benchmarks/q4-packed-reproduction.csv -KeepProfiles
```

The change improves startup chiefly by moving concatenation/packing out of the
loader and eliminating the canonical staging copy. Steady-state work loses
four vector sign-XORs per eight-row, 32-column weight block in the packed SIMD
kernels; the remaining projection arithmetic and numerical reduction order
are unchanged. The new layout is shared by the scalar/AVX2/VNNI paths, so it
does not require separate machine-specific checkpoint copies.
